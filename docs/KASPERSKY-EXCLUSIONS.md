# 卡巴斯基排除项清单（本机实测）

> 适用机器：LAPTOP-…　生成时间：2026-10-10
> 起因：卡巴斯基把 **DeepSeek Harness** 判为 `PDM:Exploit.Win32.Generic`（主动防御/行为检测，
> 类型标"木马"、级别"高"、动作"已阻止"）。

---

## 一、为什么会被判成"利用工具"

`PDM` = **主动防御模块，按行为判断，不看程序是谁**。而一次开发会话里，
DeepSeek Harness 的行为是：

- 频繁派生新进程（执行 shell 命令，几十次）
- 跨多个目录读写文件
- 调用 `adb` 操作外部设备

**这套行为画像和"远程控制后门 / 利用工具"高度重合**——检测本身没错，
区别只在于使用者是否知情并信任。本机实测的两次 `spawn EPERM`
（派生子进程失败）就是被它拦下的结果，不是沙箱问题。

## 二、要排除什么（按重要性排序）

### 1. 关键：把 Harness 设为「受信任应用程序」

**只加文件排除是不够的**——行为检测不看文件，看进程在做什么。

```
设置 → 威胁与排除 → 指定受信任应用程序 → 添加
  对象：D:\dsharness\DeepSeek Harness.exe
  勾选：☑ 不监视应用程序活动        ← 这一项才关掉 PDM
        ☑ 不扫描打开的文档
        ☑ 不扫描网络流量（可选）
```

### 2. 文件夹排除

```
设置 → 威胁与排除 → 管理排除项 → 添加
```

| 目录 | 为什么 |
|---|---|
| `D:\dsharness` | Harness 本体与运行时文件 |
| `E:\desktop\酒馆\tools\ziJi` | 项目源码、构建产物（每次编译都产生新 APK） |

### 3. 如果 `adb` 被拦（连不上手机 / 装不上包）

| 目录 | 说明 |
|---|---|
| `D:\Android\Sdk\platform-tools` | 含 `adb.exe`，会与手机建立网络连接，容易被判"网络攻击" |

### 4. 构建工具链（一般不必，除非报错指向它）

| 目录 / 程序 | 用途 |
|---|---|
| `D:\android-sdk_r24.4.1-windows\android-sdk-windows\build-tools\36.1.0\aapt2.exe` | 编译资源 |
| …同上 `\d8.bat` | dex 编译 |
| …同上 `\apksigner.bat` | 签名 |
| …同上 `\zipalign.exe` | 对齐 |
| `C:\Users\clotten\AppData\Local\Programs\FlyEnv-Data\env\java\bin\` | `javac` / `java` / `keytool` |
| `C:\Program Files\Git\cmd\git.exe` | 版本控制 |

> 这些是标准开发工具，通常不会被判恶意。**先只加第 1、2 项**，出问题再往下加。

## 三、不要做的

| 不要 | 原因 |
|---|---|
| 关掉整个卡巴斯基 | 全局失去保护，代价远大于收益 |
| 关闭「所有组件」的行为检测 | 等于对**所有程序**放弃行为监控 |
| 把整个 `D:\` 或 `E:\` 加进排除 | 排除范围过大，等于没装 |

**原则：只排除这一个程序、这两个目录。**

## 四、权衡（必须知情）

把 Harness 排除在行为检测之外，意味着**卡巴斯基不再监视它的动作**。

- 你信任它（你自己装的、正在用它做开发）→ 这是合理的
- 但这是一个**真实的监控缺口**，不是"误报白名单"那种无风险操作

如果只是临时用，可以选择：

```
设置 → 保护 → 系统监控（System Watcher）→ 暂停
```

**用完记得恢复**——这是全局开关，风险比单应用排除大得多。

## 五、DraftGuard 的 APK 有没有被拦？

**没有。** 本次被拦的全部是 `DeepSeek Harness.exe`，与 APK 无关。

如果以后在手机上侧载 APK 时被 MIUI 手机管家 / Play Protect 报警，
那份 APK 的可核对信息：

```
包名:      com.draftguard
版本:      2.27.1 (22701)
SHA256:    78EC51EB9C57A2877D1493618CEE140FDF54DF4807A468483C7401F354367CBC
大小:      78,625 字节
签名证书:  CN=typelog, OU=local, O=local, L=local, ST=local, C=CN
证书SHA256: f71748d9740ad3b36b21fceaed8d5d6a6321f6146aee4fa71e4a2139f8c3d3be
申请权限:  FOREGROUND_SERVICE、POST_NOTIFICATIONS
```

**最有力的一条：权限里没有 `INTERNET`。**
它能读别的应用的输入框，但**物理上无法把数据发出去**——
这是可验证的事实（`aapt2 dump permissions` 就能看到）。

> 补充：安卓侧载一个申请无障碍权限的应用，系统会给出"可以读取屏幕内容"的警告，
> **那个警告不要关**——它是你真正该看到的提示，也是这类能力应有的透明度。

# 已配置并验证（2026-10-10）

## 实际生效的设置

**① 文件夹排除**（威胁与排除 → 管理排除项）

```
文件或文件夹:   D:\dsharness\
检测对象类型:   *
文件哈希:       *
保护组件:       所有组件        ← 必须选"所有组件"，否则行为检测不受影响
```

**② 受信任应用程序**（威胁与排除 → 指定受信任应用程序）

```
对象: D:\dsharness\DeepSeek Harness.exe

☑ 不扫描应用程序打开的文件
☑ 不监控应用程序活动          ← 核心项，PDM 就是它拦的
☑ 不监控子应用程序活动        ← 覆盖 Harness 派生的 pwsh / adb 等
   ☑ 递归地应用排除项
☑ 不扫描所有流量
```

> **注意第 2 项和第 3 项的区别**：只勾"不监控应用程序活动"管不住**子进程**。
> 本机实测的 `spawn EPERM` 正是子进程被拦，所以"不监控子应用程序活动 + 递归"这两项
> 是必要的，不是可选项。

## 还能再补的两处（可选，不影响当前工作）

| 目录 | 为什么建议加 |
|---|---|
| `E:\desktop\酒馆\tools\ziJi` | 这里会不断生成 APK。这个 APK **在杀软眼里就是键盘记录器画像**（无障碍权限 + 自签名），将来一次全盘扫描可能把它隔离掉，导致"刚编译好就不见了"。加排除可避免 |
| `D:\Android\Sdk\platform-tools` | 含 `adb.exe`。它会与手机建立网络连接，某些情况下会被判"网络攻击"而被拒。目前实测正常，**被拦了再加** |

## 需要知情的权衡

`☑ 不扫描所有流量` 意味着**该程序的网络流量不再被拦截检查**。
对开发工具（要连模型 API）通常可接受，但这是真实的安全取舍：
卡巴斯基不再检查它的网络内容。

如果只想临时用而不长期留排除，可改用
`设置 → 保护 → 系统监控 → 暂停`，**用完记得恢复**（全局开关，风险更大）。
